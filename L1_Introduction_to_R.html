2 Rstudio

Open RStudio.

You will normally see several panes:

  • Source — where you write scripts.
  • Console — where R executes commands.
  • Environment — shows objects currently stored by R.
  • Files / Plots / Packages / Help — various tools for working with your project.

You do not need to memorise all of these yet.

  1. Find each of the following in RStudio:
    • Source
    • Console
    • Environment
    • Files
    • Help

3 Your first R commands

Click in the Console and type:

print("Hello, world!")

Press Enter.

You should see:

##  [1] "Hello, world!"

You have just given R an instruction and R has executed it.

Try:

2 + 3

and then:

10 * 5

Notice that the Console immediately executes each command.

  1. Run:
    2. print("My name is ...")

    Replace ... with your name.

  2. Then run:
    3. 2026 - 1990

    You should get a numerical result.

    Question: Where did you enter these commands, and where did you see the results?

4 Your first R script

The Console is useful for trying things, but we normally save our code in a script.

Create a new R script:

File → New File → R Script

You should now have a Source pane.

Enter:

# My first R script
print("Hello, world!")
2 + 3

Save the file:

File → Save

Name it:

lab1.R

Save it somewhere you can find it again.

Running code

Place the cursor on:

print("Hello, world!")

and run the line using Run.

The command should appear in the Console, and the result should appear there.

Run the other line as well.

  1. Add this line to your script:
    2. print("I am learning R")

    Run it.

    Then save the script again.

5 Script vs Console

You have now used both the script and the Console.

The distinction is important:

Script

  • Contains code that you want to keep
  • Can be saved
  • Can be run again later
  • Documents what you did

Console

  • Executes commands
  • Is useful for experimentation
  • Is not where you should rely on storing your work
  1. In the Console, run:
    2. print("This is only in the Console")

    Now look at your lab1.R script.

    The command is not in the script.

    If you want to keep code, put it in the script and save the script.

6 Objects

R can store information in objects.

For now, just use this simple example:

name <- "Alice"

Run it.

Look at the Environment pane.

You should see an object called name.

Now run:

name

R displays the contents of the object.

Try:

print(name)

These both display the value stored in name.

  1. Create an object containing your own name:
    2. my_name <- "..."

    Then run:

    my_name

    Look at the Environment pane.

    You should now see my_name.

    Don't worry yet about the details of <-, strings, or data types. Those will be covered later.

7 Comments

A line beginning with # is a comment.

R does not execute it.

For example:

# This is a comment 
2 + 3
# This is another comment

Comments can explain what your code does.

  1. Add a comment at the top of your script containing:
    • Your name
    • The date
    • The purpose of the script

    For example:

    # Name: ...
# Date: ...
# Purpose: First R lab

    Save the script.

8 Finding help

You will frequently need to look up how an R function works.

For example, R has a function called print().

In the Console, try:

?print

The Help pane should open.

You can also search for documentation using the Help search box.

You do not need to read the entire documentation page.

Look for:

  • What the function does
  • How it is used
  • Examples
  1. Find the documentation for mean().

    2. You can use:

    ?mean

    or search for mean in the Help pane.

    Question: What does mean() calculate?

    You don't need to use the function yet.

9 Errors are normal

Make an intentional mistake.

Run:

print("Hello"

You should get an error or an incomplete command prompt because the parentheses don't match.

Now run:

print("Hello")

The problem is fixed!

Another example:

pront("Hello")

R will report that it cannot find the function pront.

The important point is:

An error does not mean that R is broken. It means that R could not execute your instruction as written.

Read the error message. It often tells you what went wrong!

10 Reproducibility

Imagine that you perform some analysis and get an interesting result.

If the commands are only in the Console, it can be difficult to remember exactly what you did.

If your commands are saved in a script, you can run them again.

  1. Close your lab1.R script without making further changes.

    2. Open it again.

    Run the entire script.

    You should be able to reproduce the same output.

    This is one reason we write code in scripts rather than relying on the Console.
